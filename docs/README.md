# evoverse 文档

## 规则

1. **落地前只写决策过程**：待议问题进 `open-questions.md`，拍板的决策进 `adr/`。
2. **落地后才写事实**：架构、术语、阶段结果按实际代码写，一句话一条；没实现的不写。
3. **不建空文件**：下表标"待建"的文档，等有内容再创建。
4. **最简事实**：能一行说清不写一段，能表格不写散文；不复述 dsh 文档，给链接。
5. 引用 dsh 一律链接 `~/project/deepseek-harness/docs/` 原文。

## 目录

| 路径 | 内容 | 写入时机 | 状态 |
|---|---|---|---|
| `open-questions.md` | 待议议题、候选、倾向 | 讨论前/中 | 存在 |
| `adr/` | 关键决策的原因与取舍 | 拍板时 | 存在 |
| `architecture.md` | 实际服务、文件结构、数据流 | 代码落地后 | 存在 |
| `glossary.md` | 代码中实际出现的领域术语 | 术语落地后 | 待建 |
| `phases/Pn-*.md` | 该阶段做了什么 + 验收记录 | 阶段完成后 | 待建 |

## 讨论流程

1. 议题登记 `open-questions.md`。
2. 关键且难逆转的结论 → ADR；模块内部设计 → 落地时写进事实文档。
3. 勾销议题状态。
